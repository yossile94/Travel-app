# האפיון הטכני: אפליקציית מלווה טיסה ויעד

זהו **מקור האמת** של המוצר. כל שינוי בדרישה מתעדכן כאן לפני שהוא עובר לפיתוח.

## מבנה

- `overview.md`: חזון, קהל יעד ועקרונות על.
- `sprint-NN.md`: הדרישות של כל ספרינט, כפי שנכתבו באפיון.
- `CHANGELOG.md`: יומן שינויים באפיון, מה השתנה ולמה.

## פורמט פיצ'ר

לכל פיצ'ר יש מזהה ייחודי, למשל `F-012`, וקריטריוני קבלה שאפשר לבדוק:

```markdown
### F-012: <שם הפיצ'ר>

**סיפור משתמש:** בתור <משתמש>, אני רוצה <יכולת>, כדי ש<ערך>.

**קריטריוני קבלה:**
- [ ] AC-1: בהינתן <מצב>, כאשר <פעולה>, אז <תוצאה>.
- [ ] AC-2: ...

**פרטיות ורגולציה:** אילו נתונים נאספים, מי רואה אותם ולכמה זמן הם נשמרים.

**מחוץ לתכולה:** ...
```
