## 10.2 טקסים ועבודה שוטפת

- ספרינט של שבועיים: Planning, Daily של 15 דקות, Review עם דמו על מכשיר אמיתי, Retro.
- Backlog בכלי ניהול (Jira / Linear) עם User Stories, קריטריוני קבלה ו-Story Points. Refinement שבועי עם מנהל המוצר.
- דמו בכל Review מבוצע על מכשיר Android אמיתי (iOS מצטרף לפני ההשקה ב-iOS).

## 10.3 ניהול גרסאות ב-Git

- GitHub, מודל Trunk-based: main מוגן, עבודה בענפי feature/<ticket> קצרים (עד 2–3 ימים).
- כל מיזוג דרך Pull Request: Reviewer אחד לפחות, CI ירוק (lint, typecheck, בדיקות יחידה, בדיקות RLS).
- Conventional Commits ו-Semantic Versioning; תג vX.Y.Z לכל שחרור לחנויות.
- מיגרציות DB באותו repo ובאותו PR כמו הקוד שמשתמש בהן.
- שינויי JS בלבד יכולים לצאת כ-OTA (EAS Update); שינוי נייטיב או הרשאות = גרסה חדשה בחנות.
- Feature flags לפיצ'רים בפיתוח (למשל הקהילה) כדי לשחרר מ-main בלי לחשוף.

## 10.4 Definition of Done כללי

- [ ] קריטריוני הקבלה של הסטורי מתקיימים על Android (ועל iOS מהשלב שלפני ההשקה ב-iOS).
- [ ] Code Review אושר ו-CI ירוק.
- [ ] בדיקות יחידה לכל לוגיקה עסקית; בדיקת RLS לכל טבלה חדשה.
- [ ] עובד במצב offline (אם רלוונטי) ועם RTL בעברית.
- [ ] טקסטים בעברית ובאנגלית; נגישות בסיסית (VoiceOver / TalkBack, גודל גופן דינמי).
- [ ] אין מידע אישי בלוגים; אירועי אנליטיקה מתועדים.
- [ ] מופעל ב-staging ונבדק ע"י QA.
