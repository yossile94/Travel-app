# ADR-001: מבנה הפרויקט וכלי העבודה

**תאריך:** 2026-10-23
**סטטוס:** התקבל

## הקשר

אפליקציית מובייל ל-iOS ול-Android. בהמשך יתווספו פאנל אדמין (Next.js) ו-Supabase. הקוד אמור להחזיק מאות אלפי משתמשים, והפיתוח נעשה על מחשב Windows בלי Mac.

## ההחלטה

- **מאגר אחד (npm workspaces):** האפליקציה ב-`apps/mobile`. בהמשך יתווספו `apps/admin` ו-`supabase/` לידה. npm כי הוא מגיע עם Node ו-Expo תומך בו במבנה כזה בלי הגדרות.
- **Expo SDK 58 עם React Native 0.88 ו-TypeScript במצב strict**, כולל `noUncheckedIndexedAccess`. Expo Router לניווט.
- **Node 24 LTS** (`.nvmrc`). גרסת React אחת לכל המאגר (`overrides`), כי בנייה native דורשת עותק יחיד.
- **בנייה בענן (EAS):** הבנייה המקומית ב-Windows נכשלה על מגבלת נתיבים של 260 תווים ולקחה 51 דקות. שלושה פרופילים: `development` (לקוח פיתוח), `preview` (APK להתקנה ולמדידות), `e2e` (preview בלי סיבוב, לתסריטי Maestro), ו-`production`.
- **סקריפטי התקנה של חבילות:** npm 11 חוסם אותם כברירת מחדל. כל חבילה מקבלת אישור או חסימה מפורשים ב-`allowScripts`.
- **שרשרת תלויות:** גרסאות שפורסמו לפחות שבועיים לפני שמכניסים אותן, ומעדיפים ספריות קטנות ויציבות (למשל TopoJSON במקום mapshaper).

## חלופות שנשקלו

- **pnpm / yarn:** לא נדרש כרגע. npm מספיק ומונע כלי נוסף.
- **בנייה מקומית:** אפשרית רק עם שינוי הגדרת מערכת ב-Windows (long paths), ועדיין איטית מאוד.

## השלכות

- כל בנייה native עוברת בענן, במכסה החודשית של Expo. שינויי JS לא דורשים בנייה.
- ההגדרה הקפדנית של TypeScript מאטה מעט את הכתיבה, אבל תופסת שגיאות לפני המכשיר.
